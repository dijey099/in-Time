Local

Nothing to set up. Accounts are created on the Users page, with a password stored here (hashed; 12+ characters, letters and digits). Each person can change it from their account page (their name, top right).

LDAP

OpenLDAP, 389 Directory Server, FreeIPA... The account is found with the service account (or anonymously), then its password is checked by the server.

Active Directory

People log in with their Windows account: alice, EXAMPLE\alice or alice@example.local. Their password is checked by a domain controller. The reader account is only used to list the users and groups (Users and Groups pages).

{{ field('auth.ad.url', 'Domain controller URL', 'ldaps://dc1.example.local:636') }}
{{ check('auth.ad.start_tls', 'StartTLS', 'with ldap://') }} {{ check('auth.ad.verify_cert', 'Verify the server certificate') }}
{{ field('auth.ad.domain', 'Domain', 'example.local') }} {{ field('auth.ad.base_dn', 'Base DN', 'DC=example,DC=local', 'empty = from the domain') }} {{ field('auth.ad.bind_user', 'Reader account', 'svc-intime@example.local', 'to list users and groups; any domain user') }} {{ field('auth.ad.user_base', 'Users base DN', 'OU=Staff,DC=example,DC=local', 'empty = the whole domain') }} {{ field('auth.ad.group_base', 'Groups base DN', 'OU=Groups,DC=example,DC=local', 'empty = the whole domain') }}
{{ check('auth.ad.nested_groups', 'Include nested groups', 'a member of a group inside a linked group gets its role') }} {{ check('auth.ad.auto_create', 'Accounts not read yet can log in', 'new in AD since the last read, when one of their groups has a role') }} {{ test_box('ad') }}

The directory's accounts and groups are listed on Users and Groups, where you give the groups roles. A person's groups are read again at every login.
