Local

Nothing to set up. Accounts are created on the Users page, with a password stored here (hashed; 12+ characters, letters and digits). Each person can change it from their account page (their name, top right).

LDAP

OpenLDAP, 389 Directory Server, FreeIPA... The account is found with the service account (or anonymously), then its password is checked by the server.

{{ field('auth.ldap.bind_dn', 'Service account (bind DN)', 'cn=in-time,ou=services,dc=example,dc=com', 'empty = anonymous') }} {{ field('auth.ldap.user_base', 'Users base DN', 'ou=people,dc=example,dc=com') }} {{ field('auth.ldap.user_filter', 'User filter', '(uid={username})', '{username} = what is typed') }} {{ field('auth.ldap.attr_first_name', 'First name attribute', 'givenName') }} {{ field('auth.ldap.attr_last_name', 'Last name attribute', 'sn') }} {{ field('auth.ldap.attr_email', 'E-mail attribute', 'mail') }} {{ field('auth.ldap.group_base', 'Groups base DN', 'ou=groups,dc=example,dc=com', 'groups listed on the Groups page') }} {{ field('auth.ldap.group_filter', 'Group filter', '(member={dn})', '{dn} = user DN, {username}') }}

Active Directory

People log in with their Windows account: alice, EXAMPLE\alice or alice@example.local. Their password is checked by a domain controller. The reader account is only used to list the users and groups (Users and Groups pages).
